# 戦闘UI改修・計測結果

基準コミット: `61e337e`。対象: `yyvape-dev/Naraku-test` のみ。単位はCSS px、原点は画面左上。Chromium、deviceScaleFactor=1。モックは意匠参考、寸法はDOM実測。

## 実装内容

- 左上3人の円形顔・SVGコード描画の赤HP／紫狂気ゲージ・差し替え可能な装飾画像。常時数値は非表示、読み上げ用の数値は保持。
- 5枚手札の扇形配置。中央を高く・前面に置き、選択時は12px浮上・1.12倍・発光。既存の枠／キャラカード画像と金縁カード台を使用。
- 通常手札と同じ山札へ戦略カード3枚を追加。全体回復（生存者の最大HP35%、装填18秒）／他の手札引き直し（14秒）／他の空き手札の装填解除（20秒）。固定スロットなし。戦略カードは緑系の枠・個別モチーフ・名称帯・「戦略」ラベル、通常札は「スキル」ラベル。
- 手札の追加抽選には専用乱数を使用。敵が使用する従来の乱数の消費数を維持。攻撃・命中・ダメージ・敵の対象選択・既存スキル・防衛線・キャラ／VFX描画関数は変更していない。
- 戦闘中の「逆転の右手」ボタンを非表示。既存の敗北画面の巻き戻しと内部処理は維持。
- 現行版には味方の足元HPバーが存在しなかった。影・光・足元の位置はそのまま。

## 検証

- smoke.py: RESULT OK、ブラウザエラーなし。最終回の勝率は操縦・適当9/12、火力優先11/12。
- boot.py: 街→出撃→探索→戦闘→戦略カード→勝利→探索復帰→施設→記録の復元→開き直し→探索再開。ログを添付。
- battle_ui.py: 両サイズで全5枚の実タップ選択、選択札の画面内収容、操作後のcanvas原点維持、HP20%／狂気0・45・85%のゲージ、回復、引き直し時の札数保存、装填解除（通常攻撃CD不変）、80シードのランダム配置を検証。3種全てが全5位置で出現、78/80戦の初手に戦略札あり。
- 既存スキル3種を同じ順番で使用する60秒戦闘を4シードでbefore / after比較。味方HP、敵状態、撃破、報酬、与ダメージ、防衛線が一致。12秒時点の2サイズの敵状態・座標も一致。
- 390×844 / 375×667の通常表示・選択表示・ゲージ変化のスクリーンショットを目視確認。

## 懸念点・範囲

- 既存の右ステータス欄108px分は戦場の寸法維持のため残している。そこへ山札表示を置いた。モックのような全幅戦場にはしていない。
- 左上の円形UIは戦場に重なるため、その下を通る敵・VFXの一部を隠す。敵・VFXの座標、倍率、描画内容は維持したが、「重ねても一切隠さない」と「モックどおり左上へ置く」は同時に満たせない。円形UI以外の領域はクリックを遮らない。
- 5枚化と戦略札追加で手札の出現頻度・回復の機会・難易度は変わる。戦略カードの装填秒数・3/9枚の構成は仮の値。戦闘計算自体の維持と、ゲームバランスが完全同一であることは区別している。
- 未選択札の長い名称は小さく、一部が隣札に重なる。スキルは選択で拡大し、説明を表示。戦略札は即時使用後に効果名・説明を表示する。
- 左上UIのみでHP／狂気の変化と戦闘不能は識別できる。数値精度の判断は常時表示しない方針に従って省いている。実機iPhoneでのタップ感は未確認（Chromiumの2サイズで検証）。
- ステータス枠・戦略絵・カード台中央紋章は仮素材。見た目の最終仕上げには素材差し替えが必要。敗北時の巻き戻しは変更していない。
