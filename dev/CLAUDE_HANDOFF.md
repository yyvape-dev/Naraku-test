## ラナの姫騎士についても引き継ぐこと

この会話の前半で衣装切替、16枚の原画／RIFE31コマの比較、モーション速度調整を行った。その後の別更新も現行mainへ取り込まれている。

- 酒場→ラナ詳細→衣装で通常／姫騎士を切替。`naraku_lana_costume_v1` に衣装と補間選択を保存する。
- 姫騎士の通常攻撃モーションはユーザーの「1/2でちょうどよい」に合わせ **0.9秒**。通常衣装は0.45秒。高速化時は各cd以内に収める。
- 命中はモーションの55%へ同期。基準状態の姫騎士では開始後0.495秒。
- **現行ソースでは姫騎士は単なる外見差分に留まっていない。** 後続更新の `PRINCESS_D`／`charD()` により通常攻撃が直線貫通へ変わる。現在値は `atk:'line'`, `range:265`, `lineW:22`, `dmg:13`, `cd:2.3`, `far:null`。HP・スキル・超必殺のゲーム定義はラナを継承する。
- 顔・カード・カットイン・超必殺連番・白金のエフェクトも後続更新で追加されている。初回の履歴にある「顔等は従来のまま」「性能は完全共通」は現在の全体仕様ではない。
- ただし異変の属性判定では同じ `sword` として物理。白金の見た目を理由に魔法へ変えない。
- 原画は `cardart/src_lana_princess/`、比較は `mock/lana_princess.html`、検証は `tests/lana_princess.py`。後続の原画色・素材変更を、古い焼きスクリプトの再実行で上書きしない。

## ビルドと検証

リポジトリのルートから実行する。公開版は画像を埋め込まないリンク方式。

```bash
python3 dev/tools/embed.py dev/naraku_src.html index.html dev/assets --link dev/assets/
python3 -m http.server 8765
```

別のターミナルで、必要な確認を実行する。

```bash
python3 dev/tests/omens.py http://127.0.0.1:8765/index.html /tmp/omen-checks
python3 dev/tests/smoke.py http://127.0.0.1:8765/index.html
python3 dev/tools/dev/boot.py http://127.0.0.1:8765/index.html /tmp/naraku-boot.png
```

PlaywrightのChromiumが必要。実行環境でブラウザーを別ディレクトリへ入れた場合は `PLAYWRIGHT_BROWSERS_PATH` をその場所に指定する。`file://` では画像のCanvas処理を正しく検証できない。

### 確認済みの範囲と証跡の時点

- `reports/omens/checks.json`：**キャラ属性へ統一した後**の専用検証結果。物理／魔法30%、狐火・影縫い・超必殺・延焼・ゾーン、復活と報酬、通常敵／ボス、出現数、マップ、保存・移行・巻き戻し・再抽選が成功、JSエラーなし。
- `reports/omens/town-375.webp`, `town-390.webp`, `rumor-open.webp`：**1行の開閉UIへ修正した後**の画像。375/390幅で閉状態・開閉・酒場遷移・出撃ボタンを確認した。
- `reports/omens/smoke.log`：異変導入時の総合確認。RESULT OK、仮絵なし、エラーなし。異変なしの基準勝率は操縦・適当9/12、火力優先11/12。後の属性統一・UI修正で総合テスト全部を再実行した記録ではない。
- `reports/omens/boot.log`：起動→探索→戦闘→勝利→帰還→施設→写し復元→保存再開まで成功。
- `reports/omens/battles.json`：全8種・seed3・初期編成で180秒戦闘を行った**導入時の試験記録**。キャラ属性へ統一する前なので、現在の鋼／魔封じのバランス数値として引用しない。1シードの結果を難易度全体の保証にしない。
- 実機Safariの性能・表示は未確認。デスクトップのChromiumでのスマホ幅確認と区別する。

### bootの既知の確認手順上の問題

既存 `boot.py` は宿屋の `.inn-night` を2回クリックする。負荷や待機時間によっては演出が先に自動終了し、存在しない要素を待ってタイムアウトする。今回の成功ログは、同部分を「宿屋演出の自動終了を待つ」にした一時ランナーで得た。製品コードとリポジトリの `boot.py` はそのために変更していない。

同じ位置の失敗をゲームの不具合と断定せず、ログと画面を確認する。一時ランナーのファイルは環境依存なので引き継ぎ対象として当てにせず、必要なら同じ待機方法を再現する。
