# 範囲拡大・DPR・中間合成を含む解像度設計

生成・書き出し前に最大表示条件を決め、組み込み後の実画面で検証する。きれいな通常倍率の画像だけで最大範囲まで十分と判断しない。固定の1280pxや4096pxを全技・全端末の正解にしない。

## 1. 必要な画素数を実コードから求める

- ソウルカード、装備、重複強化、カメラの拡大を確認する。段数上限と加算／乗算を読み、実際にゲームの強化を適用して最大値を再現する。
- ダメージ半径と、余白を含む演出の描画領域を分ける。`r*3.2`など実際の描画幅を使う。変形・回転・風で輪郭が移動する範囲も確認する。
- CSS表示サイズ、論理座標、Canvas実ピクセル、端末DPR、ゲーム側のDPR上限、カメラの変換を区別する。横・縦の倍率が異なる場合は両軸を見る。
- 基本式は `必要な横画素 = 演出の論理描画幅 × その描画時のCanvas横倍率`。通常の倍率は `Canvas.width / 論理幅`。追加のズームがあればその変換も含める。必要数を実測し、出力画素との比を残す。
- よく使うスマホ幅だけでなくアプリが許す最大幅も調べる。小画面の結果をタブレット・Retina PCへ一般化しない。

## 2. 全工程のいちばん低い解像度を探す

`生成原本 → 使用部分の切り出し → UVとメッシュ → レンダー出力 → 縮小・圧縮 → アトラス → コマ間合成面 → ゲームCanvas → CSS表示` を追う。

素材が高解像度でも中間Canvasが224pxならそこで細部を失う。元の224px連番を1280pxへ拡大しても情報は回復しない。新たなレンダリングでも、元テクスチャの使用部分が小さければ細部はその画素密度に制限される。素材・UV・中間処理を合わせて判定する。輪郭の解像度と、材質の実際の細かさも区別する。

## 3. 品質と容量を両立させる

単純に全コマ・全レイヤを巨大化する前に、透明余白の除去、可変矩形、区画の詰め直し、前後レイヤの分離、初動と余韻のサンプル配分、独立した粒子・燃焼片の個別描画を検討する。光や煙の低周波成分と、細い炎・花弁の輪郭に同じ予算を割り当てる必要はない。

- 可変矩形は元の位置とアンカーをメタデータへ残す。詰めた画像全体を一枚の演出として拡大しない。
- 区画を使う場合は縁の余白・フィルタの色漏れ・半透明の重なり・縮小時の継ぎ目を検査する。狐火ではネイティブ解像度の合成面へ整数座標で復元してから縮小した。別の方式も実画面で検証する。
- premultiplied RGBとstraight alphaを区別し、コマ補間で中間だけ暗くしない。アルファの足切りを行うなら閾値と失う光を記録する。
- 対象環境に合わせて画像寸法・Canvas面積の上限を決める。Canvas 2DとWebGLの制約を混同しない。上限に収まらない場合、分割や構成を再検討し、黙って解像度を落とさない。

## 4. メモリ・転送量・実機性能を別々に記録する

復号メモリの基本値は `画像幅 × 高さ × 4 bytes`。これに合成面、同時に保持する比較版、個別素材、軌道配列などを加える。GPU側の複製やブラウザーの追加バッファを未測定なら総使用量と断定しない。

WebPのファイル容量は復号メモリではない。不要版の復号を止めても、HTMLへ全画像を埋め込んでいれば転送量は減らない。ファイル容量・配布物全体・復号量・描画時間・実機確認済みの範囲を分けて報告する。

## 5. 検証と成果物

通常／中間／最大の強化、複数の画面幅と実際のDPRで、必要画素・元画素・中間画素・引き伸ばし倍率を記録する。枠への収まりだけでなく、細い輪郭、色の階調、透明な縁、動くときのちらつき、敵との位置関係を実見する。

変更に応じて区画の復元、全コマの見切れ、補間、寿命、重複発動、フォールバックと戦闘処理を検証する。技術的に同じ画素を復元できたことを、迫力や自然さの合格にしない。

[設計テンプレート](../templates/design-package.md)のRESOLUTION.mdへ条件・計算・測定値・含むメモリ項目・未確認範囲を残す。

## 狐火の事例（判断の根拠であり既定値ではない）

爆心拡大は最大4段で `1.25^4=2.44140625`。基礎半径72、描画幅 `半径*3.2` のため最大562.5論理単位。393px幅・DPR2では約1228px、最大表示幅520px・DPR2では1625pxが必要だった。

旧224px連番と中間合成では不足。1280pxの直接レンダリングと同解像度での区画復元へ変更し、火の粉と燃焼片を個別描画した。393px幅までは引き伸ばし不要、520px幅では約1.27倍が残る。アトラス復号約77.6MiB＋合成面6.25MiB等へ増えた。これを全端末での解像度・性能保証とはしない。

[実測と制限](../../../../dev/reports/fox-sakura/REPORT.md)、実装は `dev/godot/fox_gust/pack.py` と `dev/naraku_src.html`。新しい技ではその技の最大条件から計算し直す。
