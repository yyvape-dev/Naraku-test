# コードで仕上げた最終演出のデザイナーレビュー

生成物のレビューと、コードで付けた動き・発光・消失のレビューは別工程。実装後にも「この技としてどう見えるか」を判断し、コードが動くことやテスト成功だけで品質を合格にしない。大きな制作・作り直しではFINISH_REVIEW.mdを残し、小修正では既存レビューの変更部分を更新する。

## レビューする完成形

実際に使うゲームの描画経路と設定で確認する。生成原画、Godot単体、UIを除いた比較場面だけで最終判定しない。通常プレイのカットイン、敵、背景、ダメージ表示、他の攻撃との重なりを含める。

発動前→投擲や予備動作→接触→ピーク→破断→余韻→完全消失を追う。命中後から始まる映像では発動全体を見たことにならない。発動時刻と命中基準の時刻を併記し、どちらの時計かを明記する。

通常・最大範囲、背景や敵の違い、必要なら重複発動を確認する。正常な再生を見た後、スロー・コマ送り・レイヤ分離で問題を特定する。比較動画は約30秒リピートを既定にする。

## 判断の残し方

各項目で **意図 → コードで加えた処理 → 実際に見えた結果と証拠 → 採用／部分採用／要修正／未確認 → 次の修正と再確認方法** を残す。関連する関数・パラメータは原因を説明するために引用する。コード名だけを見え方の証明にしない。

- **始動と命中**：予備動作の圧縮、接点、勢い、発動源から着弾への因果。飛翔や到達の手掛かりがなく突然別の場所に絵が出ていないか。見た目のピークと既存命中時刻の関係を説明できるか。
- **発光と色**：芯・中間調・薄い端の熱量差、接触光と余韻の強弱、白飛びや一律点滅。発光色を描くこと、にじみを加えること、床や敵へ光が当たって見えることを分ける。明るい素材を貼っただけで世界との光のつながりができたとしない。
- **ピークと立体感**：主役の輪郭、奥と手前の遮蔽、密度と空隙、上昇・広がり・衝撃の方向。通常攻撃／スキル／超必殺の格差。大きく明るくするだけで強い技になったとしない。敵・範囲を読める条件も評価する。
- **動きと引き渡し**：根元から先端、切れた形から飛散物への連続。共通の風を使うだけで接続を合格にしない。発生場所と時刻が実際の破断箇所に合うか。均等散会、固定輪郭の変形、意味のない乱数に戻っていないか。
- **収束と消失**：炎の首が切れる、燃料を消費する、温度が落ちる、重い片が遅れるなど、材質に合う終わり方。サイズとアルファだけの消失になっていないか。変数名がheatでもRGBを変えていなければ色温度の収束を実装したことにはならない。最後の一斉消失や、まだ攻撃中に見える残留も見る。
- **画面全体の注意とリズム**：カットイン、音がある場合の音、振動、発光、他のスキルが同じピークを奪い合っていないか。UIが主役や敵を隠さないか。カットインを外して撮った画像で通常プレイの視認性を保証しない。

## 証拠と確認限界

確認したコミット・設定・素材版、背景・敵・画面幅・DPR・強化段数、映像の時間基準を記録する。見やすくするため強化画面や通常攻撃を抑えた場合はその条件を明示し、通常プレイ全体の証拠と区別する。

連続コマで確認したこと、等速の映像で確認したこと、コードから推定したことを分ける。抽出フレームしか実見できていなければ、等速での体感・滑らかさ・音との同期は未確認とする。映像を出力しただけで再生レビュー済みにしない。

## 判定と修正

良い部分と残る弱点を両方記録する。全体の判定は「採る部分」「次に直す部分」「未確認の条件」まで具体化する。優先順位は、ゲーム上の誤読・視認性→技の因果と強弱→材質と光→微細な装飾を、その技の目的に応じて調整する。

実装・改善を依頼されている範囲では、要修正箇所をコードへ戻し、同じ場面で再確認してから提示する。レビュー・スキル化だけの依頼では、要修正を未実施の改善として記録する。修正予定を達成済みとしない。共通UIや戦闘ルールの変更まで無断で広げない。

工程をユーザーへの承認待ちに置き換えない。自分で採否と修正の優先順位を出し、具体的な成果と残る限界を提示する。
